# 可变声道布局与天空声道规划

> 状态：未来规划，不改变当前固定 5.1 实现。
> 相关文档：[PLANNING](../PLANNING.md)、[TODO](../TODO.md)、[AV Receiver](AV-RECEIVER.md)、[音频声学](AUDIO-ACOUSTICS.md)。

## 1. 目标

让接收器不再固定为 5.1，而是支持显式或自动选择的声道布局：

- mono
- stereo（2.0）
- 2.1
- 3.1
- 5.1
- 7.1
- 5.1.2
- 5.1.4
- 7.1.2
- 7.1.4
- 后续继续扩展（例如 4.1、9.1.4、TML/TMR 等）

同时新增一类天空声道扬声器：

- **天空/吸顶音响（ceiling）**：安装在天花板，向下发声。这里“天空音响”和“吸顶音响”指同一种扬声器，不再拆分向上反射式与吸顶式两种类型。

目标不是只增加几个枚举值，而是把“源声道、目标声道、物理扬声器、虚拟回退、上混/下混”拆成可独立测试的模块，避免未来继续在固定六声道代码上打补丁。

## 2. 核心原则

1. **源布局与目标布局分离**
   - 源布局来自媒体文件（ffprobe；至少知道声道数，最好知道 channel layout）。
   - 目标布局来自接收器设置：`AUTO` 或显式布局。
   - 解码器负责把源布局转换为目标布局；音频引擎只消费目标布局。

2. **物理扬声器优先，缺失声道虚拟回退**
   - 目标布局中的每个声道，优先找角色匹配且最近的已配对扬声器。
   - 没有物理扬声器时，使用该布局的标准虚拟位置。
   - 目标布局大于物理能力时，不强行裁剪源；按矩阵上混或保留虚拟声道。

3. **目标布局小于源布局时做下混**
   - 例如 5.1 源 + stereo 目标：按纯函数矩阵下混，LFE 可选择混入或丢弃。
   - 目标布局大于源布局时做上混。
   - 同布局直通，不做额外处理。

4. **不做皇帝位/声场校正**
   - 继续使用玩家实际耳朵位置和朝向。
   - 天空声道只按真实扬声器位置/虚拟标准位置渲染。
   - Seat 不参与布局或声场锁定。

5. **纯函数、可测试**
   - 上混/下混矩阵、LFE 低通、布局解析、角色映射都用纯函数。
   - 先写矩阵和声道顺序测试，再接 GUI/物理扬声器。
   - 听感仍由用户游戏内验收。

## 3. 声道模型

### 3.1 规范声道标签

首批规范标签：

| 标签 | 含义 |
|---|---|
| `M` | mono 单声道节目（规划中的可选声道） |
| `FL` / `FR` | 前置左/右 |
| `FC` | 中置 |
| `LFE` | 低频效果 |
| `SL` / `SR` | 侧环绕（7.1 使用） |
| `BL` / `BR` | 后环绕（5.1 使用；7.1 中仍保留） |
| `TFL` / `TFR` | 顶部前置左/右 |
| `TRL` / `TRR` | 顶部后置左/右 |

未来可扩展 `TML` / `TMR`（顶部中置）等，但首批不引入，避免 GUI 和布局矩阵过早复杂化。

### 3.2 首批布局

| 布局 | 声道顺序（规划） |
|---|---|
| mono | `M` |
| stereo | `FL, FR` |
| 2.1 | `FL, FR, LFE` |
| 3.1 | `FL, FR, FC, LFE` |
| 5.1 | `FL, FR, FC, LFE, BL, BR` |
| 7.1 | `FL, FR, FC, LFE, SL, SR, BL, BR` |
| 5.1.2 | `FL, FR, FC, LFE, BL, BR, TFL, TFR` |
| 5.1.4 | `FL, FR, FC, LFE, BL, BR, TFL, TFR, TRL, TRR` |
| 7.1.2 | `FL, FR, FC, LFE, SL, SR, BL, BR, TFL, TFR` |
| 7.1.4 | `FL, FR, FC, LFE, SL, SR, BL, BR, TFL, TFR, TRL, TRR` |

注意：

- 7.1 的 `SL/SR` 与 `BL/BR` 是不同声道；当前 5.1 的 `BL/BR` 不能直接当作 7.1 的侧环绕。
- 5.1.2 使用顶部前置 `TFL/TFR`；5.1.4 再增加 `TRL/TRR`。
- 具体 FFmpeg 的 channel layout 名称、声道顺序和 packing 必须在实现前用测试片验证；不能假设所有版本一致。
- mono 的落地映射需要单独决策：优先 `FC`，没有中置时回退 `FL+FR`，还是引入独立 `M` 角色。见“待确认”。

### 3.3 布局描述

规划中的 `AudioLayout` 至少包含：

```text
id                mono / stereo / 2.1 / 3.1 / 5.1 / 7.1 / 5.1.2 / ...
channels          有序的规范声道标签
ffmpegName        FFmpeg channel_layout 名（需验证）
maxChannels       物理/虚拟 source 数
hasLfe            是否含 LFE
heightChannels    天空声道集合
defaultPositions  虚拟 3D 位置（相对听者）
```

## 4. 源到目标转换

### 4.1 解码策略

建议不要让 FFmpeg 直接把所有输入强行变成目标布局；应先按 **源布局** 解码成规范声道，再由 Java 矩阵转换到目标布局：

```text
ffprobe 源布局
  → FFmpeg 解码为源布局 PCM
  → Java：源布局 → 目标布局（直通/上混/下混）
  → AudioChunk（目标布局）
  → CinemaAudioEngine（目标布局的 N 个 source）
```

原因：

- 上混/下混系数由我们控制，能测试、能调音。
- 不会因为 FFmpeg 版本的默认 matrix 改变听感。
- 未来可在矩阵里加入 LFE 分频、延迟、环绕去相关等处理。

源布局未知时：

- 至少用声道数映射到 stereo/5.1 等保守布局。
- 优先用 ffprobe 的 `channel_layout` 字段；不可用时记录警告。

### 4.2 直通 / 上混 / 下混

- 源布局 == 目标布局：直通，只做 PCM 格式转换。
- 源布局 < 目标布局：上混（upmix）。
- 源布局 > 目标布局：下混（downmix）。
- 声道标签不一致但数量相同（例如 7.1 的侧/后顺序差异）：按标签重排，不按数量猜。

首批矩阵建议：

**Stereo → 5.1**（当前已实现，保持为默认简单矩阵）：

```text
FL = L
FR = R
FC = 0.5 * (L + R)
LFE = 0.5 * lowpass120(0.5 * (L + R))
BL = 0.5 * (L - R)
BR = 0.5 * (R - L)
```

**Stereo/5.1 → 7.1**：

- FL/FR/FC/LFE/BL/BR 直通；
- SL/SR 由 BL/BR 或 L/R 差信号生成，斜率/延迟可调；
- 不做“强制把后环绕复制到侧环绕”的硬编码，矩阵单独定义。

**5.1/7.1 → 5.1.2/5.1.4**：

- 基础层直通；
- TFL/TFR 由前置 L/R 与中置的带限信号生成；
- 5.1.4 的 TRL/TRR 由后/侧环绕生成；
- 高度声道默认低通/带通，避免把全频人声塞到天空声道。

**下混**：

- 5.1 → stereo：`L = FL + 0.707*FC + 0.707*BL`，`R = FR + 0.707*FC + 0.707*BR`；LFE 可选丢弃或低电平混入。
- 7.1 → 5.1：SL/SR 按系数折叠到 BL/BR 或 FL/FR，需试听决定。
- 任何矩阵都要限幅/软削波，避免多声道求和削波。

### 4.3 LFE / 低频管理

- 2.1/3.1/5.1 等含 LFE 的布局需要明确 LFE 来源：
  - 源有 LFE：直通/低通；
  - 源无 LFE：从各声道低通提取，或由上混矩阵生成。
- 分频频率/阶数、LFE 增益、是否把小音箱低频重定向到 subwoofer，都是后续可调参数。
- 首批先保持当前简单 120 Hz 一阶低通，不做自动房间低频管理。

## 5. 新增扬声器类型

### 5.1 天空/吸顶音响（ceiling）

- 方块类型建议：`cinema:ceiling_speaker`。
- 外观：天花板嵌入式/贴顶式，发声方向朝下。
- 角色：`TFL`、`TFR`、`TRL`、`TRR`；未来可加 `TML/TMR`。
- 放置约束：需要附着在实心天花板下方；具体 blockstate/朝向/破坏规则在实现阶段设计。
- 路由层只按顶部声道处理，不再区分“向上反射式”和“吸顶式”两种扬声器类型。

### 5.2 现有扬声器角色扩展

- 落地式/书架式：新增 `SL/SR`（7.1 侧环绕）；保留 `FL/FR/BL/BR`。
- 中置：仍只允许 `FC`。
- 低音炮：仍只允许 `LFE`。
- 音箱类型决定可选角色；GUI 角色循环继续用 `SpeakerType.allowedRoles`。
- 旧存档中的 `BL/BR` 角色在 5.1 下保持原义；切换到 7.1 时不会自动改角色，需要用户重新分配或提供“按布局自动建议角色”。

## 6. 接收器与 GUI

### 6.1 布局选择

接收器 GUI 新增“布局”设置：

- `AUTO`：根据已连接物理扬声器自动选择可完整支持的最高布局。
- 显式：mono / stereo / 2.1 / 3.1 / 5.1 / 7.1 / 5.1.2 / 5.1.4 / 7.1.2 / 7.1.4。
- 显示每个声道的状态：`physical` / `virtual` / `missing` / `downmixed`。
- 切换布局不重启播放器；音频引擎重建 source 集合或复用最大 source 池。

AUTO 规则建议：

1. 收集已配对扬声器的角色集合。
2. 按布局优先级从高到低匹配所需角色。
3. 只要求基础层完整；缺失的天空/后环绕用虚拟回退，除非用户选择“严格物理布局”。
4. 无物理扬声器时不创建对应声道，不生成虚拟 5.1；是否允许用户显式选择虚拟布局由布局设置决定。

### 6.2 Speakers 页

- 继续显示已连接扬声器、名称、位置、距离、Level、Ping。
- 增加“布局角色”分组：基础层 / 侧环绕 / 后环绕 / 天空层。
- 同一角色可以分配多只扬声器；L2a 已实现每只都获得独立 direct source 并同时出声（source 预算优先保留它们）。反射与 late bus 也按每只扬声器生成，VBAP 使用全部物理扬声器到实际 5.1 声道的映射。
- 天空/吸顶音响在列表中显示类型和高度。
- 可能需要滚动/折叠分组，避免 7.1.4 时列表过长。

### 6.3 扬声器 GUI

- 新类型加入角色按钮循环。
- 显示当前布局是否使用该角色；未使用角色给出提示。
- 天空/吸顶音响可显示“顶部前置/顶部后置”用途说明。

## 7. 引擎与数据模型改造

### 7.1 CinemaAudioEngine

当前固定：

```text
CHANNELS = 6
SPEAKERS = 6
```

规划：

- 最大 source 数可配置，例如 `MAX_CHANNELS = 16`，按目标布局创建/复用。
- source 位置/增益数组长度 = 目标布局声道数。
- 每个 source 仍是一个 mono buffer；buffer 队列按 source 独立。
- `setChannelLayout` 接收 `AudioLayout` + 每声道位置/增益，不再假设 6。
- 启动/暂停/seek/时钟逻辑保持；音频时钟仍以 master source 为基准。
- OpenAL source 数量上限、多个接收器同时 7.1.4 的性能需要实测。

### 7.2 AudioChunk / 解码

```text
AudioChunk
  startPtsSeconds
  layout
  channels
  samples（按 layout.channels 顺序交织）
```

- 解码线程输出目标布局。
- `CinemaPlayer` 不再按固定 6 声道调用引擎。
- PTS 仍由源采样帧数计算；上混/下混不得改变时间轴。

### 7.3 接收器状态

`AvReceiverBlockEntity` 增加：

```text
layout            AUTO / MONO / STEREO / 2.1 / 3.1 / 5.1 / 7.1 / 5.1.2 / ...
layoutExplicit    是否用户显式选择
```

- NBT 缺失时迁移为当前 5.1。
- 通过 block entity update 同步；布局变更也可走新的 C2S action。
- 旧客户端/新客户端兼容不作为首版目标；同版本客户端/服务端即可。

### 7.4 物理扬声器路由

`AvReceiverPlayback`：

- 按目标布局遍历声道；
- 每个声道找角色匹配的已配对扬声器，取最近者；
- 计算相对玩家耳朵的 3D 位置（顶部声道保留 y 差异）；
- 无物理扬声器时使用布局默认位置；
- Level/SPL 校准继续按扬声器。
- 7.1 的 SL/SR 与 BL/BR 必须分开映射，不能共用同一只扬声器（除非用户显式把同一只分配给两个角色，仍按最近/角色规则）。

## 8. 分阶段计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| L0 | 本规划文档、布局/声道命名冻结 | 文档评审通过 |
| L1 | `AudioLayout` / 声道枚举 / 矩阵纯函数 + 单元测试 | 布局顺序、上混/下混系数、LFE 状态测试通过 |
| L2 | `CinemaAudioEngine` 动态 source 数；`AudioChunk` 带布局；5.1 回归 | 现有 5.1 播放不回归；多接收器正常 |
| L3 | Receiver 布局选择/AUTO、7.1 侧环绕、基础层 fallback | 5.1/7.1 切换；缺失声道显示正确 |
| L4 | 天空声道角色 + 虚拟顶部位置 + 5.1.2/5.1.4/7.1.2/7.1.4 | 顶部声道出声方向/位置正确；缺失天空回退正确 |
| L5 | 天空/吸顶音响方块（`ceiling_speaker`，向下发声）、模型、放置、角色限制、GUI | 该音箱可放置/配对/分配顶部角色 |
| L6 | 布局 GUI 打磨、自动角色建议、性能/多接收器验收 | 7.1.4 + 4K/BSL 下稳定；用户听感验收 |
| L7 | 声学模拟接入（`acoustic-simulation` 分支） | 高度/指向性/反射在分支听感验收后合并 |

## 9. 测试清单

- 单元：每种布局的声道顺序、源→目标矩阵、LFE 低通、限幅、7.1 侧/后区分。
- FFmpeg：确认 `5.1.2/5.1.4/7.1.2/7.1.4` 的 `channel_layout` 名称、输出顺序和可用性；不可用时用 `pan` 或自定义映射。
- 游戏内：
  - 2.0 → 5.1 上混；
  - 5.1 → stereo 下混；
  - 5.1 → 7.1（侧环绕生成）；
  - 5.1 → 5.1.2/5.1.4（天空生成）；
  - 7.1.4 物理扬声器逐一 Ping/Level/定位；
  - 缺失天空/侧环绕时的 virtual fallback；
  - 两个接收器同时不同布局；
  - 4K + BSL + 7.1.4 性能。
- 兼容：旧 5.1 存档加载；旧角色 `BL/BR` 不丢失；拆除/重放扬声器后布局自动更新。

## 10. 待确认

1. mono 落地映射：`FC` 优先还是独立 `M` 角色？
2. 5.1.2 使用 `TFL/TFR` 还是 `TML/TMR`？首批建议 `TFL/TFR`。
3. 天空/吸顶音响是否允许四只（TFL/TFR/TRL/TRR），还是只允许前置两只？
4. AUTO 布局是否允许“只匹配基础层，天空全部虚拟”，还是必须全部物理才选择该布局？
5. 7.1 的 SL/SR 与 BL/BR 下混/上混系数，需要试听决定。
6. LFE 分频频率/阶数、LFE 是否参与上混，需要试听决定。
7. 最大 source 数（16？）和多接收器同时播放的 OpenAL 资源上限。
8. 是否需要“严格物理布局”开关：缺失声道直接静音，而不是虚拟回退。
